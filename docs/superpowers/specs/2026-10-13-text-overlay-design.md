# 句子与选区悬浮翻译设计

日期：2026-10-13。状态：用户已确认，开发及现场验收进行中。

## 目标与边界

在独立、固定位置的右下角悬浮框中持续翻译当前句子或选中文本，让用户不必在选词前停下来等待。微软拼音继续负责候选生成、排序和上屏，原候选释义窗保持实时显示、候选关闭即隐藏。

用户已允许 UIA 读取当前聚焦编辑框中光标所在句，并要求翻译当前前台活动文本控件中的鼠标选区。两种方式分别提供开关，默认关闭；开启后仅内存处理，活动目标失效清除，密码框和不支持应用拒绝读取。

候选链路保持原来的系统宿主身份校验，不扩大到应用正文。正文权限只属于开启的句子或选区功能，不读取未获准的全文、剪贴板、按键历史或微软私有词库，不注入、提交候选或增加 OCR。正文只使用已启用本地模型，不自动发给在线来源。

## 悬浮框状态与主题

| 条件 | 行为 |
| --- | --- |
| 选区功能开启，存在可靠的非空文本选区 | 优先显示“选中文本”并翻译该范围；只读网页/文档不要求有输入光标 |
| 没有有效选区，句子功能开启且编辑光标处于活动输入目标 | 显示“当前句子”，翻译光标所在句 |
| 至少一个正文开关开启，但两种条件都没有 | 清空内容和任务，收成空白圆圈 |
| 两个正文开关关闭，或外挂暂停/禁用 | 框和圆圈全部隐藏，不读取正文 |

默认展开为 420×180 DIP，位于主显示器工作区右下，边距 16 DIP；圆圈直径 28 DIP。框固定位置，不跟随光标或微软候选。标题区拖动，边框/角落缩放，内容区可滚动，所有鼠标交互不得激活窗口、改变输入光标或取消原选区。

圆圈与展开框共用右下角锚点。鼠标释放后保存位置与展开尺寸，不在拖动过程中频繁写文件，不重建 reader 或模型。设置可恢复默认位置；旧表单保存须合并拖动后最新几何。跨屏、DPI 或显示器移除后限制在可见工作区，不把窗口留在屏幕外。

正文框与候选框共用 `OverlayTheme` 和 `DisplaySettings`：Windows 应用深浅色、手动主题、高对比度、背景、边框、Microsoft YaHei UI 字体、14 DIP 字号和 8 DIP 圆角一致。圆圈为圆形；状态更新原位更改内容，主题消息仅重着色，不抢焦点、不重载模型。深色使用可读浅色文字。

同模式更新期间保留上一份完整译文，同时标明它对应的原文与“更新中”，不把旧译文冒充新原文的结果。模式或活动文本目标变化时清除旧内容。空编辑句子显示“等待输入”且不发请求；不支持的已确认目标明确显示状态。

## 正文采集

复用独立 reader 的 COM MTA。正文快照包含会话、前台窗口、活动目标身份、模式、版本、文本和状态；候选关闭与活动目标失效是不同信号。两个正文开关都关闭时不创建正文扫描器，不新增候选默认路径的正文访问。

读取前后核对前台窗口、活动目标和运行时身份。切应用、同 HWND 换编辑框/文档、切按钮/菜单、密码标记、身份不确定或访问失败时先拒绝文本读取并清理旧结果，不提权绕过。

选区使用当前活动文本目标的 `TextPattern.GetSelection`：单个非退化范围才读取；退化范围是光标，空白不发请求，多个不连续范围拒绝拼接。鼠标拖选、双击与键盘选择统一处理，不安装输入钩子、不模拟 Ctrl+C。只读目标要求焦点仍属于该文档或子元素，不能扫描其他窗口、页面或后台标签页的遗留选区。

句子优先 `TextPattern2.GetCaretRange`；退化单选区可作为经过验证的插入点。只沿当前焦点元素有限父链寻找 provider，不使用 Value、Name、全文或整段 GetText 兜底。

从 caret 向两侧构建每侧最多 256 个 UIA 字符单位的范围，使用 `FindText` 和端点比较定位句界，仅对最终句子范围调用有上限的 `GetText`。中文句末 `。！？`、英文 `!?` 和换行作句界；英文句点需在末尾或后接空白，避免直接切断小数或网址。无法确认范围或字符粒度则拒绝读取。

句子与选区最多 256 个 UTF-16 字符；超限明确提示，不静默截取或补读未选上下文。选区可跨句且保留换行，不套用句子断句。句末尚无下一句内容时继续显示刚结束的句子，新行或下一句输入后切换。

使用应用提供的 `TextEditPattern.GetActiveComposition` 区分未确认 IME 文本；组合期间保留译文、标记输入中，不猜首候选。无法区分组合范围的应用在微软候选可见期间冻结句子推理，关闭后重读实际确认的正文。各应用需分别实测，不以接口存在宣称兼容。

事件只唤醒采集，限频补充检查；候选采集优先，正文读取计入现有看门狗。UIA 卡住、IPC 断开、reader 重启或配置变化清除全部旧结果。新旧 IPC 版本不混用。

## 模型与延迟

两种正文模式共用一个本地来源和一种目标语言，默认中文到英文，可选该来源支持的其他目标语言。复用 LMT Q4_K_M、GPU 优先及 CPU 回退，不加载第二份权重。没有可用本地模型时显示需要启用模型，不拼接词典释义冒充文本翻译。

正文有独立会话、模式、版本、取消与期限。稳定 300ms 后发请求，持续输入/拖选最多合并 1000ms；槽忙时只保留一个最新正文请求，不无限排队。使用与候选相同的来源生成槽，在请求边界优先最新正文，再处理候选。过期正文请求取消清理后才释放槽，不因每个按键或鼠标移动重载模型。

正文请求期限 3000ms，完整文本翻译模板、实际 chat template 与 tokenize 校验。512 总上下文，正文输出最多 128、输入最多 368、控制预留 16；候选原有 32 输出保持。输出因上限结束、输入超预算、格式无效、超时均明确显示，不降量化或联网兜底。

只有会话、目标、模式、版本、配置和模型版本匹配的结果可显示；目标失效后晚到结果不能展开圆圈。正文不进入候选 LRU、默认日志、磁盘历史或 AI 词典，仅保存当前会话显示所需的有界内容；关闭功能或失效清除。

## 设置与验收

“翻译窗 / 后台”提供句子与选区两个独立开关，默认关闭；正文来源、目标语言、合并等待、期限、重置位置为共用配置。旧 JSON 缺字段时采用默认值，在线正文来源、无效目标语言、异常几何与 token 预算拒绝。外挂全局暂停优先，停止 reader 和全部正文推理。

验收覆盖：两开关组合、真实句子输入/退格/光标移动/标点/组合取消；鼠标拖选/双击/键盘选择、只读选区、空白/退化/多范围/过长选区；同应用换目标、切应用、密码拒绝；圆圈/展开、拖动缩放不抢焦点或取消选区、几何恢复、150%/100%跨屏；两个翻译框深浅色、高对比度与主题消息；同 PID/单槽、取消、超预算、截断和故障恢复。

先执行对应失败回归、修复及回归，再在专用测试文档中实际验收。使用 Windows-MCP 前读桌面状态，USER_CONTROL 时等待空闲，不绕过保护；异常停止当轮输入，诊断、修复后重测。记录命令、退出码、通过/跳过数量和真实边界；历史候选或模型记录不代替新功能验收。

300/1000/3000ms 是调度初值，不是实测端到端延迟。性能分开统计 UIA、合并等待、排队、生成和显示的 p50/p95/p99及资源，正确性通过后再优化。
