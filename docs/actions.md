# 打包与 CI 规则（2026-10-26）

- CI 仅构建和测试。手动运行 CI 也不生成安装包，已移除 package 输入和全部打包/安装包上传步骤。
- 只有用户明确要求发布版本时，才手动运行 release.yml，填写版本标签。推送代码、创建 PR 和推送标签都不会触发发布。
- 统一入口 `scripts/Publish.ps1` 只生成发布目录，不生成或修改 ZIP。GitHub 手动 Release 验证构建后创建版本说明，不压缩或上传程序包；GitHub 自带的源码归档由平台提供。已有 Release 附件不自动删除，仍不在 Artifact 清理范围。
- 选择已有版本标签时，程序源码检出该标签，发布入口仍使用当前工作流随附的脚本，避免旧标签中的压缩逻辑重新生成 ZIP。
- CI 历史安装包全部清理，包括之前为过渡保留的最新成功包。清理必须核验来源是 ci.yml、运行已结束，并在删除后重新列举核验；运行中、来源不明或手动发布的文件不删。
- 失败测试诊断等普通临时产物仍保留 1 天。每周及默认分支 CI 结束后自动维护，忙时只审计。
